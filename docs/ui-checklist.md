# 浏览器走查清单（界面改动验收）

起服务：

```bash
cd tasks/learning/biomedical-agent-20261118
(cd web && npm install && npm run build)   # 前端是 Vite 工程，改过源码要重新构建
./run_server.sh          # 已在跑会直接提示 pid
```

地址：http://localhost:8765/ 　窗口尺寸按日常用两档：1440×900 与 800×900。

判断标准只有一条：每一行的「预期」出现即为过；出现偏差记下操作步骤、页面位置与看到的实际结果。

## 有意保留与已知取舍

- 右栏默认收起成 56px 窄条，是为了让答案列居中：1440px 下三栏常驻时中栏会被挤到偏左，收起后正文回到视觉中心。想看轨迹点窄条上的图标，一个动作就能展开。
- 生成中的呼吸点与「不要用脉动圆点表示加载」的通则冲突，保留是有意的：它绑在真正在变的流式事件上，且只有 6px。走查时不要把它记成缺陷。
- 行宽 74ch 在 1440px 下显得偏窄，是为了可读性；觉得窄可以放大到 80ch，代价是长答案行长变长。
- 流式追字的地方一律不加过渡与动画：每个 token 都会重建文字节点，加了会逐字重排。走查时若觉得「字出来得太硬」，要改的是刷新频率，不是加过渡。
- 右栏开合是页面里唯一的布局动画（`flex-basis`）。内容列有固定的行宽上限，右栏变宽时文字不重排，只整体位移。
